# MapLink

Telegram Mini App «путевой дневник»: отмечаешь на 3D-глобусе побывавшие места и мечты,
собираешь полароиды и boarding passes, а друзья видят твою ленту и совпадения по странам.

Приложение живёт в одном файле `index.html` — это осознанное решение (легко отдавать
другой модели целиком), а не случайность. Всё остальное в репозитории — инструменты и доки.

- В демо: <https://tengizka.github.io/MapLink/>
- Бот: `@MapLinkAppbot` → `/MapLink`
- Стек: один HTML + Supabase (Postgres + Storage) + MapLibre GL, деплой на GitHub Pages

## Запуск и отладка

Локально — любой статический сервер:

```bash
python3 -m http.server 8080
# затем открыть http://localhost:8080/?demo=1
```

Снаружи Telegram приложение работает **только на чтение**: без `?demo=1` оно показывает
экран «открой в Telegram» и вообще не трогает базу, с `?demo=1` — интерфейс живой,
но ни один insert/update/delete в Supabase не уходит (см. `docs/SECURITY.md`).

## Проверки

Перед коммитом любой правки:

```bash
cd tools/verify
npm install
npm run verify
```

Это jsdom-бут настоящего `index.html` в трёх режимах (Telegram / браузер-demo / браузер-без
Telegram) плюс статические проверки: синтаксис JS, валидность CSS, «`getElementById` на id,
которого нет в разметке», и end-to-end XSS-проба — в DOM подсовывается payload в `username`,
`note`, `country`, `avatar_url` и `display_name`, и проверка падает, если из него получается
живой `<img onerror>` или происходит breakout из атрибута. Перед XSS-пробой прогон
кликами проходит по всей нижней навигации, чтобы каждый экран успел отрисоваться.
`scan-xss.mjs` — статический поиск данных, вставленных в HTML без экранирования
(ловит отсутствующий `esc()` даже там, куда клики не дошли).

## Структура

```
index.html                     всё приложение: стили + разметка + скрипт
assets/puzzle.jpg              картинка для подарочной головоломки
docs/SECURITY.md               модель угроз, что закрыто, что осталось
supabase/migrations/           ссылка на схему + опциональное усиление RLS
supabase/functions/            заготовка Edge Function для проверки initData
tools/verify/                  проверка сборки/XSS/разметки (jsdom)
```

## Правила проекта

Главный свод правил — в **шапке `index.html`**: это HTML-комментарий перед `<html>`.
Он обращается к тому, кто правит код (обычно к модели), и там зафиксированы:
что можно трогать в базе, требования к дизайну, известные баг-паттерны WebView
и обязательное правило экранирования. Не удаляй его и обновляй, если меняешь правила.
